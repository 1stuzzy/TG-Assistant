# TG Manager

Панель управления Telegram-аккаунтами: список аккаунтов, авторизация
по номеру телефона (код + 2FA), проверка активности сессии и удаление
аккаунта (с реальным `log_out` в Telegram).

## Структура проекта

```
telegram-manager/
├── backend/                     # FastAPI + Telethon
│   ├── app/
│   │   ├── config.py             # настройки из .env
│   │   ├── main.py               # точка входа FastAPI
│   │   ├── schemas.py            # pydantic-схемы запросов/ответов
│   │   ├── models/
│   │   │   └── account.py        # класс Account, enum AccountStatus
│   │   ├── services/
│   │   │   ├── account_store.py       # AccountStore — хранение в JSON
│   │   │   └── telegram_manager.py    # TelegramAccountManager — логика Telethon
│   │   └── api/
│   │       └── routes.py         # REST-эндпоинты
│   ├── requirements.txt
│   ├── .env.example
│   └── run.py                    # запуск сервера
├── frontend/                    # статический клиент (без сборки)
│   ├── index.html
│   ├── css/styles.css
│   └── js/
│       ├── api.js                # класс ApiClient (обёртка над fetch)
│       ├── accounts.js           # класс AccountsView (список, поиск)
│       ├── wizard.js             # класс LoginWizard (мастер входа)
│       └── app.js                # класс App — связывает всё вместе
└── data/
    ├── accounts.json             # метаданные аккаунтов (создаётся сам)
    └── sessions/                 # .session-файлы Telethon
```

Архитектура разделена на слои с чёткой ответственностью (ООП):

- **`Account`** — доменная модель одной записи аккаунта.
- **`AccountStore`** — репозиторий, ничего не знает о Telegram, отвечает
  только за чтение/запись JSON.
- **`TelegramAccountManager`** — вся работа с Telegram API через Telethon
  (запрос кода, подтверждение, 2FA, проверка статуса, logout).
- **`api/routes.py`** — тонкий HTTP-слой поверх менеджера.
- На фронтенде симметрично: `ApiClient` (сеть) → `AccountsView` /
  `LoginWizard` (UI-логика) → `App` (композиция).

## 1. Получите API-ключи Telegram

1. Зайдите на https://my.telegram.org и войдите под своим номером.
2. Откройте **API development tools** и создайте приложение.
3. Скопируйте `api_id` и `api_hash`.

## 2. Настройте и запустите backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# впишите в .env свои TG_API_ID и TG_API_HASH

python run.py
```

Сервер поднимется на `http://localhost:8000`. Панель открывайте сразу там же:
`http://localhost:8000` (backend сам отдаёт frontend). Проверка:
`http://localhost:8000/health` → `{"ok": true}`.

Первый запуск `pip install` качает CPU-сборку `llama-cpp-python` — это движок нейросети без видеокарты.

## 3. ИИ-агент (диалог как человек)

Агент сидит на **сохранённой Telethon-сессии** того аккаунта, который вы добавили в панели. Отдельный Pyrogram-скрипт из `Telegram/` для этого не нужен: одна сессия не должна быть открыта двумя клиентами сразу.

### Какую модель взять (CPU, без GPU)

Кладите `.gguf` в `data/models/` или загрузите файл во вкладке **Настройки**.

| Модель | Файл ~ | RAM | Скорость на CPU | Когда брать |
|---|---|---|---|---|
| **Qwen2.5 1.5B Instruct Q4_K_M** | 1 ГБ | ~3 ГБ | очень быстро | проверка, что всё отвечает |
| **Qwen2.5 3B Instruct Q4_K_M** | 2 ГБ | ~5 ГБ | быстро | **рекомендуется** для живого диалога |
| **Qwen2.5 7B Instruct Q4_K_M** | 4.7 ГБ | ~8 ГБ | медленнее | если качество важнее скорости |

Почему так: GGUF + llama.cpp считает на процессоре (AVX). Q4_K_M — нормальный компромисс качество/скорость. Русский язык у Qwen2.5 для такого размера лучший среди открытых CPU-моделей. 7B уже «умнее», но на слабом CPU ответ может идти 5–15 секунд.

Не берите для CPU: полноразмерные 13B+, GGUF Q8 (тяжелые), PyTorch `.safetensors` без квантизации.

### Как протестировать

1. Запустите backend (`python run.py`) и откройте `http://localhost:8000`.
2. Добавьте аккаунт (номер → код → 2FA при необходимости). Сессия сохранится в `data/sessions/`.
3. В **Настройки → Модели** загрузите `.gguf` (например Qwen2.5 3B).
4. На карточке аккаунта нажмите **ИИ-агент**, выберите модель, запустите.
5. Напишите этому аккаунту в личку с другого Telegram — агент прочитает непрочитанные диалоги и будет отвечать на новые сообщения. В группы не пишет.
6. **Стоп ИИ** — останавливает агента. Пока он запущен, не нажимайте «Проверить» у этого же аккаунта: файл сессии занят.

Первый ответ после старта может занять 20–60 секунд (модель грузится в RAM).

## Как работает вход в аккаунт

1. **Номер телефона** → `POST /api/accounts/login/start` создаёт
   Telethon-клиент, вызывает `send_code_request` — Telegram присылает
   код в приложение или SMS.
2. **Код** → `POST /api/accounts/login/code` вызывает `sign_in`. Если
   у аккаунта включена двухфакторная аутентификация, Telethon бросает
   `SessionPasswordNeededError`, и API возвращает `need_2fa`.
3. **2FA-пароль** (если нужен) → `POST /api/accounts/login/password`
   завершает вход через `sign_in(password=...)`.
4. После успешного входа Telethon сохраняет `.session`-файл в
   `data/sessions/`, а `AccountStore` сохраняет метаданные в
   `data/accounts.json`.

**Проверка** (`POST /api/accounts/{id}/check`) переподключается по
сохранённой сессии и вызывает `is_user_authorized()`.

**Удаление** (`DELETE /api/accounts/{id}`) вызывает `client.log_out()`
(реально завершает сессию на стороне Telegram), затем удаляет
`.session`-файл и запись из `accounts.json`.

## Важно

- Каждый аккаунт, который вы подключаете, должен принадлежать вам или
  вы должны иметь право им управлять — вход выполняется официальным
  способом через Telegram API, но массовая автоматизация чужих
  аккаунтов нарушает [условия использования Telegram](https://core.telegram.org/api/terms).
  Соблюдайте разумные лимиты запросов, чтобы не получить временный бан
  за flood-контроль.
- `data/accounts.json` и файлы в `data/sessions/` дают полный доступ к
  аккаунтам — храните их так же аккуратно, как пароли, не публикуйте
  и не коммитьте в общий репозиторий (уже добавлено в `.gitignore`).
- Это учебный/стартовый каркас: для продакшена стоит добавить
  аутентификацию самого API, HTTPS, очередь задач для длительных
  Telegram-вызовов и БД вместо JSON-файла.
